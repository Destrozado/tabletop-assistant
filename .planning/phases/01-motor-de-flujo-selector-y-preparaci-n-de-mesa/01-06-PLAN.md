<threat_model>
## Trust Boundaries

Este plan introduce la **primera exposición pública** del proyecto: hasta aquí todo vivía en el portátil.

| Boundary | Description |
|----------|-------------|
| repositorio local → GitHub (público o privado) | Todo el contenido del repo pasa a estar alojado por un tercero |
| GitHub → build de Netlify → CDN público | Un tercero ejecuta el build y sirve el resultado en internet |
| internet → sitio estático publicado | Cualquiera con la URL puede cargar la app; no hay superficie de escritura, ni API, ni datos de usuario en el servidor |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-14 | Information Disclosure | Publicación del repositorio y del sitio | mitigate | Antes del push, comprobar que `.gitignore` cubre `node_modules/`, `.nuxt/`, `.output/` y `*.log`, y que no existe ningún `.env` ni credencial en el árbol. El proyecto no tiene secretos por diseño (sin backend, sin claves de API), pero la comprobación se hace explícitamente antes del primer push, no se asume |
| T-01-08 | Information Disclosure (riesgo legal) | Contenido de reglas ahora accesible públicamente | accept | El contenido es redacción propia, breve e imperativa, con citas como punteros de datos y sin reproducir cartas, arte ni texto extenso del reglamento (PROJECT.md). El uso sigue siendo privado del grupo; si en el futuro se quisiera difusión amplia, conviene reevaluar y considerar repositorio privado |
| T-01-15 | Tampering | Build de terceros (Netlify) ejecutando el código del repo | transfer | Netlify construye desde un commit concreto del repositorio; el mismo gate de CI (`npm run test`) que corre en GitHub Actions valida el contenido. Cualquier manipulación exigiría comprometer la cuenta de GitHub o la de Netlify, ambas bajo control exclusivo del usuario |
| T-01-16 | Denial of Service | Disponibilidad del sitio publicado | accept | Sitio estático en CDN, sin backend que saturar; y desde la Fase 4 la caché offline elimina la dependencia de red durante la partida |
| T-01-17 | Spoofing | Cuentas de GitHub y Netlify | transfer | Credenciales y autenticación de dos factores son responsabilidad del usuario; Claude no las posee ni debe pedirlas (D-16). Ninguna tarea de este plan debe intentar autenticarse ni almacenar tokens |
</threat_model>
