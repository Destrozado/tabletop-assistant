```typescript
  const willAnnounce = shouldAnnounce({ kind, state: voiceState.value, line: spokenLine.value, isSupported: isSupported.value })
```

**Scope-disposal pattern** (`tryOnScopeDispose`, lines 177, 204) — any new resource


descarga los audios pregenerados. Clave `voice-audio-v1`."

**Defensive silent-failure pattern to copy exactly** (lines 76-105) — every browser
storage call in this codebase is wrapped in `try/catch` that swallows the error and
returns "absence", never propagates:
```typescript
function readRaw(key: string): string | undefined {
  if (typeof window === 'undefined') return undefined
  try {
    return window.localStorage.getItem(key) ?? undefined
  }
  catch {
    return undefined
  }
}
```
Apply the identical shape to `fetch`/`cache.match`/`cache.put` in `prefetchAll` — this
is also explicitly what D-07 requires (silent fallback, never an error the user sees).
RESEARCH.md's Pattern 3 code example already follows this shape (`try { ... } catch {

the load-bearing precedent, cross-checked against the real `usePersistedSession.ts`
convention it was clearly modeled on.

**SSR-safety guard to copy** — every browser-global access in this codebase is
preceded by `typeof window === 'undefined'` (line 77, 87, 98) or the equivalent
`'caches' in window` check (already in RESEARCH.md's draft) — never assume a browser
global exists unconditionally, this project prerenders (`nuxt generate`) and the
composable body can run during that step.

**Return-shape convention** — `usePersistedSession` returns a plain object of named
functions (`{ load, save, clear, loadVoicePreference, saveVoicePreference }`, line
149), no reactive refs exposed for its imperative helpers. `usePreloadedAudio` is
different in kind (it needs a queryable `Map` and must expose an async
`prefetchAll(ids)` plus a synchronous accessor for `announce()` to read
without awaiting) — do not force it into the same shape; RESEARCH.md's sketch (`const
preloaded = new Map<string, string>()`, exposed via a `get`/`has`-style accessor) is
the right shape for *this* composable's actual constraint (Pitfall 1: the read from
`announce()` must be synchronous, never `await Map.get(...)`).

### `engine/resolve.ts` (utility, transform — MODIFY, add `resolveAudioId`)

**Analog:** itself. Full file read (17 lines).

**Exact pattern to mirror** — `resolveText` reads `context.difficulty` off
`node.step.variants?.difficulty` and falls back to the base field; `resolveAudioId`
must branch on the identical condition (not reimplement variant-detection logic):
```typescript
// engine/resolve.ts (current, full file)
import type { RuntimeStepNode, SessionContext, TextBlock } from './types'

export function resolveText(node: RuntimeStepNode, context: SessionContext): TextBlock {
  const variant = node.step.variants?.difficulty?.[context.difficulty]
  return {
    text: variant?.text ?? node.step.text,
    warning: variant?.warning ?? node.step.warning,
    warningDetail: variant?.warningDetail ?? node.step.warningDetail,
    options: variant?.options ?? node.step.options,
    optionsWarning: variant?.optionsWarning ?? node.step.optionsWarning,
    speech: variant?.speech ?? node.step.speech,
  }
}
```
Add `resolveAudioId` in the same file, same header-comment convention (a one-line
"what this does and why" comment above the function, matching the file's existing
opening comment about not doing arithmetic/token substitution). RESEARCH.md's draft
is correct and should be used verbatim:
```typescript
export function resolveAudioId(node: RuntimeStepNode, context: SessionContext): string {
  const hasVariant = node.step.variants?.difficulty?.[context.difficulty] !== undefined
  return hasVariant ? `${node.step.id}.${context.difficulty}` : node.step.id
}
```
This file has no error handling (it's a pure function over already-validated data) —
follow that convention: no try/catch here, defensiveness belongs at the call site
(`useVoiceAnnouncer.ts`) where browser I/O actually happens.

## Shared Patterns

### Silent-degradation-on-failure (D-07, D-08, VOZ-06/UI-08)
**Source:** `app/composables/usePersistedSession.ts` lines 76-105 (localStorage),
`app/composables/useVoiceAnnouncer.ts` lines 233-241, 259-264 (speech synthesis),
`app/pages/[game]/index.vue` lines 123, 247, 267 (wake lock)
**Apply to:** `usePreloadedAudio.ts` (fetch/cache failures), the new branch in
`announce()` (`audioEl.play()` rejection).
```typescript
// The one repeated shape across this entire codebase for "this can fail, and
// failure must never surface":
try {
  /* browser API call */
}
catch {
  // explicit comment citing the decision id that mandates silence
}
```
No new error type, no logging, no user-visible banner — every existing analog treats
failure as indistinguishable from absence.

### Comment-as-contract convention
**Source:** every file read in this phase (`content.test.ts`, `useVoiceAnnouncer.ts`,
`usePersistedSession.ts`, `index.vue`, `resolve.ts`)
**Apply to:** all new/modified files.
Every non-trivial function in this codebase is preceded by a comment that names the
decision id(s) it satisfies (`D-XX`, `VOZ-XX`, `G-01`) and explains *why*, not just
*what*. The planner's tasks should require the same discipline for new code — this is
not optional style, it is how future gates/regressions get traced back to a decision.

### Generic traversal over hardcoded id lists
**Source:** `engine/__tests__/content.test.ts` lines 13-19 (`allSteps`), line 215-226
(`variants.difficulty` steps derived programmatically, never pasted as a literal pair)
**Apply to:** `voice-drift.test.ts`'s id-collection helper, and `scripts/voice/generate.mjs`'s
step-enumeration loop — both must derive the 33+4 = 37 ids by walking the validated
`GameDefinition`, never by copy-pasting the id list found in RESEARCH.md.

### Vitest project/glob convention
**Source:** `vitest.config.ts` lines 11-19 (`engine` project: `include:
['engine/**/*.test.ts']`, `environment: 'node'`)
**Apply to:** `engine/__tests__/voice-drift.test.ts` — placing it under `engine/__tests__/`
