<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| registro npm → build local/CI | Se introduce una dependencia nueva de build (`@vite-pwa/nuxt`) que genera código que se ejecutará en el navegador de la tablet |
| host estático (Vercel) → navegador | El navegador decide si hay una versión nueva basándose exclusivamente en las cabeceras con que el host sirve `/sw.js` |
| service worker → app instalada | A partir de este plan existe un proceso que puede interceptar y responder cualquier petición del origen |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-SC | Tampering | `npm install @vite-pwa/nuxt` | mitigate | Legitimidad ya auditada en `04-RESEARCH.md` §Package Legitimacy Audit (slopcheck 0.6.1 → `2 OK`, ambos `Approved`, sin `postinstall`, repo `github.com/vite-pwa/nuxt`, ~157k descargas/semana). Versión fijada a `1.1.1`; CI usa `npm ci` contra el lockfile |
| T-04-01 | Tampering | `/sw.js` servido con caché larga | mitigate | Cabecera `no-cache` en `routeRules` verificada en Task 2 contra `.vercel/output/config.json`, no asumida |
| T-04-02 | Denial of Service (percibido) | Service worker rancio que nunca cede el control | mitigate | `registerType: 'prompt'` + `no-cache` en `/sw.js`: el navegador siempre re-consulta si hay build nueva; el plan 04-05 añade la superficie para aplicarla |
| T-04-03 | Elevation of Privilege | Alcance del service worker (`scope: '/'`) | accept | El origen sirve exclusivamente esta app estática; no hay contenido de terceros ni subrutas de otro propietario que un SW de alcance raíz pudiera secuestrar |
| T-04-04 | Spoofing | `start_url`/`scope` del manifiesto | mitigate | Ambos declarados como rutas relativas al propio origen (`'/'`), nunca como URL absoluta a otro dominio |
</threat_model>
